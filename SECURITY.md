# Security policy

## Supported versions

Security reports are accepted for the latest tagged release and `main`.

| Version | Supported |
| --- | --- |
| Latest tagged release | Yes |
| `main` | Yes |
| Older releases | No |

## Reporting a vulnerability

Use this repository's GitHub private vulnerability reporting:
open the **Security** tab and select **Report a vulnerability**.

If that channel is unavailable, contact the maintainer privately through
GitHub to arrange a confidential report.

Never open a public Issue for a vulnerability.

Include:

- The affected file and version, tag, or commit.
- Steps to reproduce the issue, with a minimal example if possible.
- The expected security impact.

## Response expectations

We aim to acknowledge reports within 7 days.
This is a response target, not a guaranteed resolution time.
There is no bug bounty program.

## Scope

This kit consists of documentation, prompts, and shell/Python tooling.
Installer and checker scripts are in scope for security reports.
