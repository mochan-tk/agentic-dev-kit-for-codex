# Contributor instructions

This repository distributes a source-first workflow kit. Read
[CONTRIBUTING.md](CONTRIBUTING.md), [product scope](docs/product-scope.md), and
the current Issue or pull request before changing files.

- Record the objective, acceptance criteria, verification, risks and owned
  paths before implementation. Keep one active writer for each branch,
  worktree and overlapping scope; preserve other contributors' changes.
- GitHub Issues, pull requests, commits and current checks are the durable
  work record. Sessions and role names do not authenticate authority.
- Keep the installed payload separate from contributor instructions. Changes
  to payload bytes, classes, modes or installer behavior require an explicit
  product change with updated provenance and relevant regression evidence.
- Run the product checks and relevant tests before reporting a result. Missing,
  stale or uncheckable evidence is non-success. State skipped tests and limits.
- Humans retain agreement, exception, acceptance and merge authority. Do not
  merge, bypass protection, change permissions or send messages without scope
  and authority for that action. Sensors observe; setup and publishing act.
- Publish only bounded evidence. Keep credentials, private paths, raw logs,
  transcripts and adopter recovery records out of commits, Issues and artifacts.
- Durable product artifacts use English. Read [provenance](docs/provenance.md)
  for predecessor records; those records are not this repository's work orders.

The product does not promise native Windows qualification, cross-client runtime
parity, authenticated roles, automatic updates or a universal control plane.
