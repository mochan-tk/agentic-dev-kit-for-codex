## One usable product target

The target is a reviewed local-source kit with eight Skills, three source-role
definitions, durable Issue/PR procedures, explicit optional helpers, and safe
installation/update/recovery. The frozen behavioral source is
`mochan-tk/agentic-dev-kit-for-copilot@fd265ddef150fab86cd54d0e383c2c25fe297ffb`.
The fixed 47-file payload and its original source blobs remain unchanged.
Do not export kit-development Task IDs, context pins, sole-active policy,
qualification infrastructure or CI as adopter truth.

Completion review must address every SF criterion at one exact candidate head:
either current direct evidence, or a human-reviewed equivalence argument for
explicitly named historical evidence and unchanged relevant bytes. Missing,
stale, failed, `UNKNOWN`, `UNCHECKABLE`, unmeasured or unapproved clauses remain
pending; they are not waived by an applicability label. This Task does not
perform new elicitation, service writes, client qualification or adopter use.

## Traceability, not a second result store

The closed machine record is
[`source-first-completion.v1.json`](../../.github/governance/source-first-completion.v1.json).
It binds this definition, the accepted baseline, source/payload provenance and
protected inputs. Every original K01-K20 appears once with its original text
digest and a primary SF criterion. Every original scenario appears once in
catalog order with its ID, title, exact expected-text digest and rationale.

- `retained`: the named behavior is relevant to this product; this does not
  assert implementation, measurement or satisfaction.
- `adapted`: the product requires the stated narrower/source-native slice;
  additional clauses of the original expectation remain separately required
  by the original DoD. The row explicitly identifies the missing distinction.
- `supplemental`: the original runtime/platform/full-parity obligation remains
  unchanged outside this narrower product target. It is not approved-deviation,
  not a scenario pass and not an exemption in the canonical catalog.

Applicability counts are inventory counts, never progress percentages. Mixed
expectations are adapted rather than silently retained in full. For example,
an optional board is not a measured stale-board warning; declarations/diff
checks are not envelope execution; preserved configuration is not measured
drift reporting; three source roles are not six native agents. Exhaustive
per-Skill/cross-surface invocation remains supplemental, but selected-client
installed-Skill use remains required by SF-10.

## Evidence classes and recoverable references

The machine record lists bounded public references with explicit classes:
source provenance, historical public owner acceptance, planning observation,
public aggregate, and historical required CI. Shipped static instructions and
real Bash/disposable fixtures with synthetic GitHub are separately identified
required evidence, not newly measured results in this record. Classes do not imply success outside
their scope. A GitHub URL is a durable locator, not offline proof of its current
body. No live URL fetch, GitHub write or runtime action occurs in the checker.

Private adopter identifiers, URLs, worker references and evidence must remain
private. Public aggregate references establish only the published aggregate;
the owner must privately verify the underlying records before an SF-10 outcome.
Do not publish a digest of an unverified private record as a substitute. No
raw logs, transcripts, credentials, environment values or private paths belong
in this contract. Historical records remain historical; current CI evidence is
recorded externally against the PR, not hard-coded to the future PR's own SHA.

## Codex adaptations and separate obligations

Project-parent nesting in the Copilot app was a platform workaround. Project
coordination spans sibling Epics; Epic -> Task -> Worker remains intended
delegation. A documented/capability-proven surface or durable manual handoff
is required. No agent is assumed to control sibling threads natively. The
source's three roles and no shipped hook assets do not justify claiming six
runtime roles or hooks complete. Original K09-K12/H obligations remain open.

Local-only/no-force installation, explicit apply, known-old update and bounded
operation rollback are intentional adaptations. Arbitrary partial bytes,
power loss and concurrent edits are not guaranteed recoverable. Windows
execution, generalized sensor coverage, live feedback delivery, sufficient
context, authenticated roles and full runtime parity need their own evidence.
T12 remains paused and unaccepted; no VM qualification is a prerequisite for
the source-first installer. The original release DoD is neither deleted nor
weakened by this distinction.

## Deterministic enforcement and changes

The existing mandatory `check-repository-policy.py` calls the dedicated
validator unconditionally; existing conformance discovery runs
`test_source_first_completion.py`. No second registry, workflow or framework
is added. The guard reads bounded no-follow regular files, rejects malformed
or non-unique JSON, limits parsed depth/nodes/strings, checks closed fields,
all IDs and referenced bytes, and pins the reviewed canonical v1 record.
Rehashing a modified definition inside the data cannot approve a new contract.
The seal is integrity against this reviewed checker, not a signature or an
adversarial protection against jointly changing trusted code and data.

Future changes to scope, evidence classes, applicability or protected source
bindings require an owner-reviewed agreement change with corresponding exact
ownership, checker and tests. This snapshot remains incomplete even after a
later GitHub acceptance; external current-outcome authority resolves chronology.
