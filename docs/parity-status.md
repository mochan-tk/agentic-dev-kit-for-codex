The cache reuses one successfully read state per identity within a process;
each new invocation refetches. Dependency membership is still validated for
every Task. An OPEN blocker does not skip later observations. Unknown, failed,
incomplete or inconsistent data refuses the entire result before a partial
frontier can be printed. This is not an atomic GitHub snapshot or lock.

Only the frontier engine and its exact ritual adoption-anchor compatibility
change in this package; all 47 payload paths/classes/modes and the other 45
contents remain unchanged. The separate adopter-CI sensor's supported ritual
digest is synchronized, without changing its workflow semantics or migrating
an installed addon. Its deployment and guarded-file transitions remain explicit.
The legacy 47-file updater does not update an existing addon's old sensor or
configuration digest; setup refuses non-identical existing addon files. Those
installations therefore need a separate owner-reviewed transition. A fresh
candidate deployment would not prove existing-addon migration. Inert improvement
templates also cannot simply be added to the addon's closed workflow inventory.

Acceptance of implementation, synthetic evidence, historical adopter use and
current live measurement must be recorded separately. No blanket full-parity,
product-final or release acceptance follows from this table. T12 remains paused,
`release_blocked=true` remains in force, and the original 136 scenarios stay
`not-run` with `results: []`. No existing-adopter, service, schedule or runtime
operation is authorized by this document.
